# 《轻页》App 软件需求文档

版本：v1.0  
日期：2026-06-05  
状态：初稿  

## 1. 产品概述

### 1.1 App 名称

**轻页**

### 1.2 命名说明

“轻页”强调两个核心特征：

- **轻**：打开快、使用简单，不做复杂编辑器，不增加阅读负担。
- **页**：面向 Markdown、HTML、网页式文档和文本页面的手机阅读场景。

英文名可暂定为 **LightPage**。

### 1.3 产品定位

轻页是一款手机端 Markdown / HTML 文件阅读器，主要解决微信、文件管理器、邮箱、网盘等移动端场景中 `.md`、`.markdown`、`.html`、`.htm` 文件难打开、难阅读、难转发的问题。

第一版产品聚焦“收到文件后快速打开并舒服阅读”，不做复杂内容创作工具，也不做云文档平台。

### 1.4 一句话定义

**轻页是一款手机端 Markdown / HTML 阅读器，支持从微信、文件管理器、邮箱等入口直接打开文件，在本地安全渲染，并提供适合手机阅读的搜索、目录、字号、主题、导出 PDF 和分享能力。**

### 1.5 第一版范围

第一个版本必须包含前期规划中的 **P0** 与 **P1** 所有功能。

第一版主路径：

1. 用户在微信或其他 App 中收到 Markdown / HTML 文件。
2. 用户通过“用其他应用打开”选择轻页。
3. 轻页自动识别文件类型和编码。
4. 轻页进入阅读页并完成渲染。
5. 用户可阅读、搜索、查看目录、调整字号和主题。
6. 用户可保存到 App 内、收藏、复制全文、导出 PDF 或分享图片。

## 2. 背景与问题

### 2.1 背景

越来越多的人用 Markdown 和 HTML 传递文档、说明、报告、技术资料、AI 生成内容和网页式材料。但在手机端，尤其是微信环境中，这两类文件并不具备良好的原生预览能力。

### 2.2 核心问题

1. 微信不支持 Markdown 和 HTML 文件的顺畅预览。
2. 用户从微信中选择其他 App 打开文件的路径复杂。
3. 普通用户不知道应该用什么 App 打开 `.md` 或 `.html` 文件。
4. 现有工具往往偏编辑器或开发者工具，不适合移动端快速阅读。
5. HTML 文件在手机上可能存在脚本安全、外部资源、相对路径、乱码和布局溢出等问题。
6. 用户外出时只想快速阅读或转成 PDF / 图片发回微信，不想折腾文件管理器或浏览器。

## 3. 目标用户

### 3.1 主要用户

1. 经常在微信、邮箱、网盘中接收 Markdown / HTML 文件的人。
2. 需要在手机上临时阅读 AI 生成文档、技术说明、会议材料的人。
3. 需要把 Markdown / HTML 内容转成微信更容易查看格式的人。
4. 需要本地阅读工作资料、内部文档、代码说明的人。

### 3.2 次要用户

1. 程序员、产品经理、运营、研究人员。
2. 经常阅读 Markdown 笔记或 HTML 报告的用户。
3. 需要查看代码块、表格、长文档的移动端用户。

## 4. 产品原则

1. **阅读优先**：第一版是阅读器，不是编辑器。
2. **打开要快**：从外部 App 打开后应直接进入阅读页。
3. **本地优先**：默认不上传文件内容，不依赖账号。
4. **安全渲染**：HTML 默认使用安全沙盒策略。
5. **移动端友好**：表格、代码块、图片、长文档必须适配手机屏幕。
6. **弱打扰**：首页和阅读页都应简洁，不引入不必要的信息流或社区功能。
7. **兜底可用**：渲染失败时至少能查看源码或纯文本。

## 5. 使用场景

### 5.1 微信收到 Markdown 文件

用户在微信中收到 `.md` 文件，点击文件后微信无法正常预览。用户选择“用其他应用打开”，选择轻页。轻页直接打开文件并渲染为适合手机阅读的文章。

### 5.2 微信收到 HTML 文件

用户在微信群中收到 `.html` 文件。用户用轻页打开后，轻页在安全沙盒中渲染 HTML，默认禁用危险脚本，并对外部资源加载进行提示或限制。

### 5.3 外出时快速查看资料

用户在外面没有电脑，只能用手机处理别人发来的文档。用户通过轻页打开文件，使用搜索和目录快速定位重点内容。

### 5.4 转成微信更容易看的格式

用户打开 Markdown 或 HTML 后，需要把内容转给其他人。轻页支持导出 PDF、分享图片、复制全文或分享原文件。

### 5.5 再次打开历史文件

用户之前从微信打开过一份文档，后来想再次查看。轻页首页的最近打开列表展示该文件，用户点击后继续阅读，并恢复上次阅读位置。

## 6. 信息架构

### 6.1 首页

首页应包含以下模块：

1. 最近打开
2. 收藏
3. 文件库
4. 打开文件
5. 粘贴打开，可作为入口保留，但第一版不要求复杂处理

### 6.2 阅读页

阅读页应包含以下区域：

1. 顶部栏
   - 返回
   - 文件名
   - 搜索
   - 目录
   - 更多菜单

2. 内容区
   - Markdown 渲染视图
   - HTML 渲染视图
   - 源码 / 纯文本兜底视图

3. 阅读工具
   - 字号调节
   - 主题切换
   - 阅读进度
   - 导出
   - 分享

4. 更多菜单
   - 保存到文件库
   - 收藏 / 取消收藏
   - 查看源码
   - 导出 PDF
   - 分享图片
   - 分享原文件
   - 复制全文
   - 文件信息
   - 编码设置

## 7. 功能需求

## 7.1 文件打开

### 7.1.1 从外部 App 打开文件

优先级：P0

需求描述：

轻页必须支持从微信、文件管理器、邮箱、网盘等 App 中通过系统“用其他应用打开”或分享菜单打开 Markdown / HTML 文件。

功能要求：

1. 支持注册以下文件类型：
   - `.md`
   - `.markdown`
   - `.html`
   - `.htm`

2. 支持从以下来源打开：
   - 微信
   - 系统文件管理器
   - 邮箱附件
   - 网盘 App
   - 系统分享菜单

3. 从外部 App 打开文件后，轻页应直接进入阅读页。

4. 打开过程中应显示加载状态。

5. 打开失败时应展示明确失败原因和可用兜底操作。

验收标准：

1. 用户从微信中对 `.md` 文件选择轻页后，App 能打开并渲染内容。
2. 用户从微信中对 `.html` 文件选择轻页后，App 能打开并渲染内容。
3. 用户从系统文件管理器打开上述文件类型后，App 能正常处理。
4. 文件无法渲染时，用户仍可进入源码或纯文本视图。

### 7.1.2 手动选择文件

优先级：P0

需求描述：

用户可以在轻页首页点击“打开文件”，从系统文件选择器中手动选择 Markdown / HTML 文件。

功能要求：

1. 支持系统文件选择器。
2. 默认筛选支持的文件类型。
3. 允许用户选择文件后进入阅读页。
4. 支持中文文件名、空格、括号和常见特殊字符。

验收标准：

1. 用户可以从本地文件中选择 `.md`、`.markdown`、`.html`、`.htm` 文件。
2. 中文文件名和包含空格的文件名能正常展示。

## 7.2 Markdown 阅读

### 7.2.1 Markdown 渲染

优先级：P0

需求描述：

轻页必须支持常见 Markdown 和 GitHub Flavored Markdown 语法渲染。

功能要求：

1. 支持标题。
2. 支持段落。
3. 支持加粗。
4. 支持斜体。
5. 支持删除线。
6. 支持有序列表。
7. 支持无序列表。
8. 支持引用块。
9. 支持分割线。
10. 支持链接。
11. 支持图片。
12. 支持行内代码。
13. 支持代码块。
14. 支持表格。
15. 支持任务列表。
16. 支持自动链接。
17. 支持 fenced code block。

验收标准：

1. 常见 Markdown 文档在轻页中能正确显示标题、段落、列表、引用、图片、表格和代码块。
2. GitHub Flavored Markdown 的表格、任务列表、删除线和 fenced code block 能正确显示。
3. Markdown 渲染不应破坏手机页面布局。

### 7.2.2 代码块显示

优先级：P0

需求描述：

Markdown 中的代码块应适合手机阅读。

功能要求：

1. 支持代码块语法高亮。
2. 支持常见语言：
   - JavaScript
   - TypeScript
   - Python
   - Java
   - C
   - C++
   - C#
   - Go
   - Rust
   - Shell
   - JSON
   - XML
   - HTML
   - CSS
   - SQL

3. 代码块支持横向滚动。
4. 长代码块不得撑破页面。
5. 行内代码应有明确视觉样式。

验收标准：

1. 长代码行不会导致整页横向溢出。
2. 常见语言代码块具有基础高亮效果。

### 7.2.3 Markdown 图片显示

优先级：P0

需求描述：

Markdown 中的图片应尽量正常显示，并适配手机屏幕。

功能要求：

1. 支持远程图片显示。
2. 支持同目录相对路径图片显示。
3. 支持常见图片格式：
   - PNG
   - JPG
   - JPEG
   - WebP
   - GIF
   - SVG

4. 图片默认自适应屏幕宽度。
5. 图片加载失败时显示占位和路径提示。

验收标准：

1. Markdown 中的有效图片能正常显示。
2. 图片宽度不超过内容区。
3. 图片加载失败时用户能看到失败提示，而不是页面空白。

### 7.2.4 Markdown 自动目录

优先级：P1

需求描述：

轻页应根据 Markdown 标题自动生成目录。

功能要求：

1. 根据 `#` 到 `######` 标题生成目录。
2. 支持点击目录项跳转到对应标题。
3. 支持目录折叠 / 展开。
4. 支持当前阅读位置高亮。
5. 支持返回原阅读位置。

验收标准：

1. 包含多个标题的 Markdown 文档能生成目录。
2. 点击目录项能跳转到正确位置。
3. 滚动阅读时目录能反映当前位置。

## 7.3 HTML 阅读

### 7.3.1 HTML 渲染

优先级：P0

需求描述：

轻页必须支持 HTML 文件打开和渲染。

功能要求：

1. 支持 `.html` 和 `.htm` 文件。
2. 支持完整 HTML 文档。
3. 支持 HTML 片段。
4. 支持内联 CSS。
5. 支持基础外链 CSS。
6. 支持同目录图片资源。
7. 缺失资源时应提示。

验收标准：

1. 标准 HTML 文件可以被打开并显示。
2. HTML 片段可以被包装为可读页面显示。
3. 缺失图片或 CSS 不应导致 App 崩溃。

### 7.3.2 HTML 移动端适配

优先级：P0

需求描述：

HTML 文件应在手机屏幕上具备可读性。

功能要求：

1. 自动适配手机屏幕宽度。
2. 图片默认不超过内容区宽度。
3. 宽表格支持横向滚动。
4. 代码块支持横向滚动。
5. 长链接、长文本应避免撑破页面。
6. 提供基础阅读模式或样式优化。

验收标准：

1. 宽表格不会导致整页布局错乱。
2. HTML 页面主体内容在竖屏下可正常阅读。
3. 图片和代码块不会遮挡其他内容。

### 7.3.3 HTML 安全沙盒

优先级：P1

需求描述：

HTML 文件可能包含脚本、外部资源和恶意行为。轻页必须以安全策略渲染 HTML。

功能要求：

1. 默认在沙盒环境中渲染 HTML。
2. 默认禁用危险脚本执行。
3. 默认阻止自动跳转。
4. 默认阻止自动下载。
5. 外部链接跳转前提示用户。
6. 外部资源加载策略可配置。
7. 用户可以选择“信任此文件”。
8. 信任状态应仅对当前文件或明确范围生效。

验收标准：

1. 包含自动跳转脚本的 HTML 文件不会自动跳转。
2. 包含自动下载逻辑的 HTML 文件不会自动下载。
3. 点击外部链接前 App 会提示用户。
4. 用户关闭外部资源加载时，HTML 不应加载远程资源。

### 7.3.4 HTML 外部资源提示

优先级：P1

需求描述：

HTML 可能引用外部图片、CSS、字体或脚本。轻页应让用户知道这些资源是否被加载。

功能要求：

1. 发现外部资源时提供提示。
2. 支持用户允许或拒绝加载外部资源。
3. 支持设置默认策略：
   - 始终询问
   - 默认阻止
   - 默认允许，仅限用户信任文件

4. 资源加载失败时显示提示。

验收标准：

1. HTML 引用远程图片或 CSS 时，用户可以控制是否加载。
2. 外部资源加载失败不影响主体内容阅读。

### 7.3.5 HTML 自动目录

优先级：P1

需求描述：

轻页应根据 HTML 中的标题结构生成目录。

功能要求：

1. 根据 `h1` 到 `h6` 自动生成目录。
2. 支持点击跳转。
3. 支持当前阅读位置高亮。
4. 支持折叠 / 展开目录。

验收标准：

1. 包含标题标签的 HTML 文件能生成目录。
2. 点击目录项能跳转到对应标题位置。

## 7.4 阅读体验

### 7.4.1 手机阅读排版

优先级：P0

需求描述：

Markdown 和 HTML 的渲染结果必须适合手机阅读。

功能要求：

1. 内容区应有合适边距。
2. 段落行高应适合长时间阅读。
3. 标题层级应清晰。
4. 表格支持横向滚动。
5. 代码块支持横向滚动。
6. 图片自适应宽度。
7. 内容不应与顶部栏、底部工具栏重叠。

验收标准：

1. 在主流手机竖屏尺寸下，正文可读且不横向溢出。
2. 表格、代码、图片均不破坏整体页面。

### 7.4.2 深浅色模式

优先级：P0

需求描述：

轻页必须支持浅色和深色阅读主题。

功能要求：

1. 支持浅色模式。
2. 支持深色模式。
3. 支持跟随系统主题。
4. 主题切换后立即生效。
5. 主题设置应被保存。

验收标准：

1. 用户可以在阅读页切换浅色和深色模式。
2. 重启 App 后保留上次主题设置。
3. 深色模式下正文、代码块、表格和链接均清晰可读。

### 7.4.3 字号调节

优先级：P0

需求描述：

用户可以根据手机屏幕和视力习惯调整阅读字号。

功能要求：

1. 支持正文字号调节。
2. 支持至少 5 档字号。
3. 标题、段落、列表应随正文设置合理缩放。
4. 代码块字号可随正文缩放，或提供独立设置。
5. 字号设置应被保存。

验收标准：

1. 用户可以在阅读页调整字号。
2. 字号调整后文档布局仍保持正常。
3. 重启 App 后保留字号设置。

### 7.4.4 文内搜索

优先级：P0

需求描述：

用户可以在当前文档内搜索关键词。

功能要求：

1. 支持输入关键词搜索。
2. 高亮匹配项。
3. 显示匹配数量。
4. 支持上一个 / 下一个匹配项跳转。
5. 搜索无结果时显示提示。
6. 搜索关闭后应清除高亮。

验收标准：

1. 用户输入关键词后可以看到所有匹配项高亮。
2. 用户可以跳转到上一处和下一处匹配结果。
3. 搜索结果数量显示准确。

### 7.4.5 阅读位置记忆

优先级：P1

需求描述：

轻页应记住用户上次阅读位置。

功能要求：

1. 记录每个文件的最后阅读位置。
2. 再次打开文件时恢复到上次位置。
3. 用户可手动回到顶部。
4. 文件内容发生变化时，应尽量恢复到接近位置；无法恢复时回到顶部并提示。

验收标准：

1. 用户关闭文件后再次打开，可以回到上次阅读位置。
2. 用户可以一键回到顶部。

### 7.4.6 表格与代码块横向滚动

优先级：P1

需求描述：

Markdown 和 HTML 中的宽表格、长代码块必须支持横向滚动，避免页面整体溢出。

功能要求：

1. 表格容器支持横向滚动。
2. 代码块容器支持横向滚动。
3. 横向滚动区域应有清晰边界或视觉提示。
4. 表格和代码块不能挤压正文布局。

验收标准：

1. 包含多列宽表格的文档可正常阅读。
2. 包含长代码行的文档不会导致整页横向滚动。

## 7.5 文件记录与管理

### 7.5.1 最近打开

优先级：P0

需求描述：

轻页应记录用户最近打开的文件，方便再次查看。

功能要求：

1. 首页展示最近打开列表。
2. 每条记录显示：
   - 文件名
   - 文件类型
   - 文件大小
   - 最近打开时间

3. 点击记录可重新打开文件。
4. 外部文件失效或权限丢失时提示用户重新选择。
5. 支持从最近打开中移除记录。

验收标准：

1. 用户打开文件后，该文件出现在最近打开列表。
2. 用户点击最近打开记录可以再次查看文件。
3. 文件不存在时 App 给出明确提示。

### 7.5.2 保存到 App 内文件库

优先级：P1

需求描述：

用户可以将外部打开的文件保存到轻页的本地文件库。

功能要求：

1. 阅读页提供“保存到文件库”入口。
2. 保存后文件可在首页文件库中查看。
3. 文件库展示文件名、类型、大小、保存时间。
4. 支持删除 App 内本地副本。
5. 保存到 App 内的文件不依赖外部路径。

验收标准：

1. 用户从微信打开文件后，可以保存到 App 内文件库。
2. 即使外部原文件不可访问，App 内保存副本仍可打开。
3. 用户可以删除 App 内保存的文件。

### 7.5.3 收藏

优先级：P1

需求描述：

用户可以收藏常用文档。

功能要求：

1. 阅读页支持收藏 / 取消收藏。
2. 首页提供收藏列表。
3. 收藏列表显示文件名、类型、收藏时间。
4. 删除文件时应同步处理收藏状态。

验收标准：

1. 用户可以收藏当前文件。
2. 被收藏文件出现在收藏列表。
3. 取消收藏后文件从收藏列表移除。

### 7.5.4 中文和特殊文件名兼容

优先级：P1

需求描述：

轻页应正确处理中文文件名、空格和常见特殊字符。

功能要求：

1. 支持中文文件名。
2. 支持包含空格的文件名。
3. 支持包含括号的文件名。
4. 支持常见符号，如 `-`、`_`、`.`、`@`。
5. 文件名显示不得乱码。

验收标准：

1. 中文文件名能在首页、阅读页和导出文件中正常展示。
2. 特殊字符文件名不影响打开、保存、收藏和分享。

优先级：P0

需求描述：

用户可以将当前 Markdown / HTML 文档导出为 PDF。

功能要求：

4. 支持 HTML 导出 PDF。
5. 导出完成后可调起系统分享面板。
6. 导出失败时显示原因。

验收标准：

1. 用户可以将 Markdown 文档导出为 PDF。
2. 用户可以将 HTML 文档导出为 PDF。
3. 导出的 PDF 可以被微信、文件管理器或系统 PDF 预览器打开。

### 7.6.2 复制全文

优先级：P0

需求描述：

用户可以复制当前文档的全文内容。

功能要求：

1. Markdown 支持复制原文。
2. HTML 支持复制可读纯文本。
3. 源码视图支持复制源码。
4. 复制完成后显示成功提示。

验收标准：

1. 用户可以复制 Markdown 全文。
2. 用户可以复制 HTML 提取后的纯文本。
3. 剪贴板内容与用户选择的复制模式一致。

### 7.6.3 分享原文件

优先级：P1

需求描述：

用户可以将当前原始 `.md` 或 `.html` 文件分享给其他 App。

功能要求：

1. 阅读页提供分享原文件入口。
2. 支持分享外部打开文件。
3. 支持分享 App 内保存文件。
4. 分享失败时显示提示。

验收标准：

1. 用户可以从轻页将原始 Markdown / HTML 文件转发到微信或其他 App。

### 7.6.4 分享为图片

优先级：P1

需求描述：

用户可以将当前阅读内容分享为图片。

功能要求：

1. 支持将当前可见区域导出为图片。

验收标准：

1. 用户可以将当前阅读区域分享为图片。

## 7.7 编码与异常处理

### 7.7.1 编码识别

优先级：P0

需求描述：

轻页应自动识别常见文本编码，降低乱码概率。

功能要求：

1. 自动识别 UTF-8。
2. 自动识别 UTF-8 with BOM。
3. 自动识别 GBK / GB2312。
4. 编码异常时提供手动切换入口。
5. 用户选择编码后重新渲染文档。

验收标准：

1. UTF-8 Markdown / HTML 能正常显示中文。
2. GBK / GB2312 文件能尽量正常显示中文。
3. 出现乱码时用户可以切换编码并重新渲染。

### 7.7.2 打开失败兜底

优先级：P0

需求描述：

任何异常文件都不应导致 App 崩溃。轻页应提供源码或纯文本兜底。

功能要求：

1. Markdown 渲染失败时可切换纯文本视图。
2. HTML 渲染失败时可切换源码视图。
3. 文件不是有效 Markdown / HTML 时应提示。
4. 文件过大时应提示可能影响性能。
5. 文件权限失效时应提示用户重新选择。
6. 异常提示应包含可能原因。

验收标准：

1. 异常 Markdown 文件不会导致 App 崩溃。
2. 异常 HTML 文件不会导致 App 崩溃。
3. 用户至少可以查看原始文本内容。

### 7.7.3 打开失败提示文案

优先级：P1

需求描述：

打开失败时，轻页应给出具体、可理解的提示。

功能要求：

失败原因至少包括：

1. 文件不是有效 Markdown / HTML。
2. 文件编码不支持或识别失败。
3. HTML 依赖同目录资源，但当前只导入了单个 HTML。
4. 文件过大，当前设备可能无法流畅渲染。
5. 外部文件已被删除或权限失效。

验收标准：

1. 打开失败时用户能看到明确原因。
2. 提示中包含下一步操作建议，例如“查看源码”“切换编码”“重新选择文件”。

## 8. 非功能需求

## 8.1 性能

优先级：P0

2. HTML 渲染失败时可以切换源码视图。
3. Markdown 渲染失败时可以切换纯文本视图。

优先级：P1

需求要求：

1. Markdown 渲染在本地完成。
2. HTML 渲染在本地沙盒完成。

4. 默认阻止自动跳转。

6. 外部链接跳转前提示。
7. 外部资源加载策略可配置。

## 8.4 隐私

优先级：P1

需求要求：

1. 核心阅读功能不需要账号。
2. 默认不上传文件内容。
3. 不采集文件正文。
4. 崩溃日志不得包含文档内容。
5. 用户保存到 App 内的文件仅保存在本地。

## 8.5 兼容性

优先级：P1

需求要求：

1. 支持主流 iOS 和 Android 手机。

6. 支持系统深浅色模式。

## 12. 数据对象

## 12.1 文件记录

字段建议：

1. `id`：文件记录唯一标识。
2. `fileName`：文件名。
3. `fileExtension`：文件扩展名。
4. `fileType`：Markdown / HTML / Text。
5. `fileSize`：文件大小。
6. `sourceType`：来源类型，例如微信、文件管理器、邮箱、网盘、App 内。
7. `sourceUri`：外部文件引用地址。
8. `localPath`：App 内保存路径。
9. `encoding`：识别或用户选择的编码。
10. `lastOpenedAt`：最近打开时间。
11. `createdAt`：创建时间。
12. `isFavorite`：是否收藏。
13. `lastReadPosition`：最近阅读位置。
14. `trustedHtml`：是否信任该 HTML 文件。

## 12.2 用户设置

字段建议：

1. `themeMode`：浅色 / 深色 / 跟随系统。
2. `fontSizeLevel`：字号档位。
3. `lineHeight`：行高设置，可选。
4. `externalResourcePolicy`：外部资源加载策略。
5. `defaultEncoding`：默认编码策略。
6. `restoreReadingPosition`：是否恢复阅读位置。

## 13. 主要流程

## 13.1 从微信打开文件

1. 用户在微信中点击文件。
2. 用户选择“用其他应用打开”。
3. 用户选择轻页。
4. 轻页接收文件 URI。
5. 轻页识别文件类型。
6. 轻页识别文件编码。
7. 轻页进入阅读页。
8. 轻页渲染 Markdown 或 HTML。
9. 用户阅读、搜索、导出或保存文件。

## 13.2 手动打开文件

1. 用户进入轻页首页。
2. 用户点击“打开文件”。
3. 系统文件选择器打开。
4. 用户选择文件。
5. 轻页识别文件类型和编码。
6. 轻页进入阅读页并渲染。

## 13.3 导出 PDF

1. 用户在阅读页点击导出 PDF。
2. 轻页基于当前渲染内容生成 PDF。
3. 轻页显示导出进度。
4. 导出成功后调起系统分享面板。
5. 用户选择微信、文件管理器或其他 App。

## 13.4 收藏文件

1. 用户在阅读页点击收藏。
2. 轻页更新文件记录。
3. 首页收藏列表展示该文件。
4. 用户再次点击取消收藏后，文件从收藏列表移除。

## 15. 风险与约束

### 15.1 微信文件打开限制

微信对文件打开方式和路径权限可能存在平台差异。App 需要适配 iOS 和 Android 的系统文件分享、打开和沙盒机制。

### 15.2 HTML 安全风险

HTML 文件可能包含恶意脚本、外部资源、自动跳转、自动下载等行为。必须优先保证安全，默认采用沙盒策略。

### 15.3 HTML 资源缺失

用户经常只收到单个 HTML 文件，而该 HTML 可能依赖同目录图片、CSS 或 JS。第一版应提示资源缺失，但不要求完整支持文件夹导入。

### 15.4 大文件性能

超大 Markdown / HTML 文件可能导致渲染慢或内存占用高。第一版需要提示风险，并提供源码 / 纯文本兜底。

### 15.5 编码识别不准确

部分文件编码可能无法自动准确识别。第一版需要提供手动切换编码能力。
