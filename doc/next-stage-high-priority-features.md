# 《轻页》下一阶段高优先级开发功能规划

版本：v1.2 规划稿  
日期：2026-08-01  
适用平台：Android、Windows 10/11  
规划基线：LightPage v1.1.2

## 1. 阶段结论

下一阶段不再以“补齐基础阅读器能力”为主，而是围绕两个平台形成清晰分工：

- **Android**：强化“收到文件后立即阅读、批注并分享”的移动闭环。
- **Windows**：强化“管理本地资料、并行阅读并跟随文件变化”的桌面工作台。
- **共享底座**：继续提升大文档渲染、搜索、资源缓存和异常恢复能力，保持本地优先与安全渲染原则。

本规划为 Android 与 Windows **各提出 9 个高优先级功能点**，每个平台在特色功能、交互性、性能三个方面各 3 项。P0 是下一阶段发布承诺，P1 是高优先级增强项，必须在 P0 稳定后进入。

## 2. 当前能力与规划边界

### 2.1 已有能力

v1.1.2 已具备 Markdown、HTML 和纯文本阅读，GFM、代码高亮、KaTeX、Mermaid、目录、文内搜索、主题与排版设置、最近记录、收藏、文件库、阅读位置恢复、图片/PDF/原文件导出，以及 HTML 安全沙盒。

Android 已支持外部 App 打开与 ZIP/RAR 文档包；Windows 已支持 Markdown 文件关联、单实例唤起、同目录图片和桌面安装包。因此，本阶段不重复规划上述基础能力。

### 2.2 优先级定义

| 优先级 | 定义 | 发布规则 |
| --- | --- | --- |
| P0 | 直接改善主路径成功率、平台差异化或大文件稳定性 | 全部通过验收后才能发布 v1.2 |
| P1 | 高价值增强，但不阻断核心主路径 | P0 稳定后按收益/成本顺序交付，可进入 v1.2.x |

### 2.3 本阶段非目标

- 不建设账号、云同步、团队协作或在线文档平台。
- 不扩展为完整 Markdown/HTML 编辑器，仅允许批注、书签等轻量阅读产物。
- 不默认上传正文，不将在线 AI 摘要作为本阶段依赖。
- 不扩大 HTML 默认权限；脚本、远程资源和外部跳转仍遵循最小授权。

## 3. Android 高优先级功能

### 3.1 特色功能

#### A-F1 压缩包连续阅读模式（P0）

将目前“从 ZIP/RAR 中选一个文件打开”升级为文档包阅读：展示包内目录，支持上一篇/下一篇、阅读状态和最近位置，并允许只收藏包内某篇文档。

**验收标准：** 支持的压缩包可在不重复解压的情况下连续切换文档；退出后可恢复到原压缩包、原文档及原章节；损坏、加密和超限文件继续执行现有安全拦截。

#### A-F2 本地高亮、书签与批注（P0）

支持选中文本后高亮或添加短批注，并将书签定位到标题和文本上下文；所有数据仅保存在本机，可导出为 Markdown 批注摘要。

**验收标准：** 新增、修改、删除和跳转操作完整可用；文档未变化时定位成功率 100%；文档轻微变化时能够按上下文重新定位，无法定位时明确标记为“待重新关联”。

#### A-F3 移动分享卡片（P1）

在现有图片导出的基础上增加“选中文段生成卡片”，提供 3 套内置模板、来源标题、主题色、二维码开关和分享前预览，适配微信等聊天场景。

**验收标准：** 用户可在 3 步内完成选段、预览和系统分享；生成过程不上传正文；常见长段落能自动分页且不截断文字。

### 3.2 交互性

#### A-I1 外部打开任务队列与无缝续读（P0）

统一处理冷启动、后台唤醒和运行中连续收到的 VIEW/SEND 请求，避免新文件覆盖正在处理的文件；提供“继续当前文档”或“打开新文档”的轻提示。

**验收标准：** 冷启动、后台和前台各连续执行 30 次外部打开无请求丢失、错序或重复；返回键行为符合 Android 导航习惯；失败项可从最近任务中重试。

#### A-I2 沉浸阅读与手势导航（P1）

增加单击隐藏工具栏、边缘轻扫呼出目录、双击恢复默认缩放和音量键翻页（默认关闭）等可配置能力，同时兼容系统手势返回。

**验收标准：** 所有手势均可单独关闭；不会拦截正文选择、表格横向滚动、代码块滚动和系统返回；TalkBack 下仍可完成等价操作。

#### A-I3 平板、横屏与折叠屏自适应（P1）

在宽屏下采用“文件列表/目录 + 正文”双栏布局，折叠状态变化时保持当前文档和阅读位置；支持窗口化模式的最小可用宽度。

**验收标准：** 手机竖屏、手机横屏、7–12 英寸平板及一种折叠屏尺寸无控件遮挡；旋转和折叠切换后阅读位置偏差不超过一个视口。

### 3.3 性能

#### A-P1 外部文件极速首屏（P0）

缩短 Intent 解析、文件复制、编码识别和首屏渲染链路；优先展示可读首屏，目录、代码高亮和图表随后补齐。

**验收标准：** 主流中端 Android 设备上，1 MB 本地 Markdown 从选择轻页到正文首屏可见 P95 ≤ 1.0 秒，5 MB P95 ≤ 2.0 秒；性能回归超过 10% 时阻断发布。

#### A-P2 长文档渐进渲染与视口回收（P0）

按章节分块解析和渲染，对离屏代码块、表格、公式与 Mermaid 延迟初始化；保留锚点、搜索和阅读进度语义。

**验收标准：** 10 MB 测试文档可在 2 秒内进入可操作状态；持续滚动无明显长时间白屏，慢帧率低于 5%；新增内存峰值以 120 MB 为候选上限，并在目标设备基线后锁定。

#### A-P3 原生流式 I/O 与缓存配额（P1）

文件读取、解压、校验和导出尽量使用流式处理；建立按大小和最近使用时间回收的正文、资源和临时文件缓存，低存储空间时主动降级。

**验收标准：** 100 MB 压缩包处理期间不生成重复的全量内存副本；缓存可查看、可清理；系统存储不足时中止操作并清理临时文件，不造成崩溃或孤儿数据。

## 4. Windows 高优先级功能

### 4.1 特色功能

#### W-F1 文件夹工作区（P0）

允许用户授权一个或多个资料目录，按目录树浏览 Markdown/HTML 文件，并将文件夹作为可移除的工作区保存；不复制原文件，文件库继续保留独立语义。

**验收标准：** 可添加、移除、重命名工作区并恢复上次展开状态；仅访问用户明确选择的目录；文件失效或目录离线时有可恢复提示。

#### W-F2 外部修改实时刷新（P0）

监听当前文件及其相对资源变化，在编辑器或生成工具写入后自动刷新阅读结果；刷新前保留当前标题、搜索状态和相对阅读位置。

**验收标准：** 保存文件后 500 ms 内出现刷新结果；连续写入使用防抖且不重复闪烁；文件被删除、替换或编码改变时提供明确状态和重新打开入口。

#### W-F3 多标签与并排对照阅读（P1）

支持多文档标签页、最近关闭恢复，以及两个文档并排查看；每个标签独立保存搜索、目录和阅读位置。

**验收标准：** 可同时打开至少 20 个标签；重启后按设置恢复标签；并排模式支持独立滚动与可选的标题同步，关闭未持久保存的批注前必须提示。

### 4.2 交互性

#### W-I1 拖放与批量打开（P0）

支持将单个文件、多个文件或文件夹拖入窗口；文件进入标签或打开队列，文件夹进入工作区添加流程，并提供格式不支持的汇总提示。

**验收标准：** 一次拖入 100 个混合文件时界面不中断，可打开的文档保持原顺序；不可打开项只提示一次汇总，不影响有效文件。

#### W-I2 全键盘操作与命令面板（P0）

提供统一命令面板及可发现的快捷键，覆盖打开、切换标签、搜索、目录、主题、字号、导出、收藏和关闭等高频操作。

**验收标准：** 不使用鼠标即可完成核心阅读流程；快捷键冲突可检测并恢复默认值；关键控件具备清晰焦点样式和无障碍名称。

#### W-I3 窗口状态与系统集成完善（P1）

记忆窗口大小、位置、最大化状态和侧栏宽度；补齐可选 HTML 文件关联、“打开方式”入口和任务栏最近文档，设置中可随时撤销关联。

**验收标准：** 多显示器拔插后窗口仍在可见区域；文件关联安装、修改和卸载无残留；从资源管理器启动时复用现有实例并正确聚焦目标文档。

### 4.3 性能

#### W-P1 工作区增量索引与全文检索（P0）

为授权工作区建立本地索引，初次扫描后只处理新增或变化文件；搜索返回文件名、标题、正文片段和匹配位置，不把正文上传到外部服务。

**验收标准：** 10,000 个文件的元数据扫描可取消且不阻塞界面；1,000 个常规文档完成索引后，关键词查询 P95 ≤ 100 ms；索引损坏可自动重建。

#### W-P2 大文档增量解析与稳定滚动（P0）

复用共享分块渲染能力，并针对桌面宽表格、大代码块和多列布局优化；文件刷新时尽量只更新变化章节。

**验收标准：** 20 MB Markdown 在推荐配置上 2 秒内进入可操作状态；单章修改不触发全文 DOM 重建；长文连续滚动期间交互保持可响应。

#### W-P3 重型内容与导出任务隔离（P1）

Mermaid、代码高亮、全文图片和 PDF 导出进入懒加载或独立任务，增加取消、进度与资源上限，避免阻塞主阅读窗口。

**验收标准：** 首屏外图表不提前渲染；导出可取消且临时资源会回收；复杂文档导出期间仍可切换标签和搜索，失败不会破坏当前阅读会话。

## 5. 跨平台共用建设

以下工作不单独计入两端的 9 项功能，但应作为实现前提：

1. 建立统一的 `DocumentSession`、批注锚点、文件变化事件和分块渲染协议，避免两端各自维护一套正文状态。
2. 将平台能力封装为明确接口：Android Intent/SAF/分享，Windows 文件监听/工作区/窗口管理。
3. 元数据增加版本号和迁移日志；升级失败必须保留旧数据并允许重试。
4. 性能记录只保存文件大小分档、耗时、内存和错误码，不记录正文、搜索词或文件绝对路径。
5. 为 1/5/10/20 MB 文档、1,000/10,000 文件工作区、复杂 Mermaid 和超大表格建立固定回归语料。

## 6. 推荐实施顺序

建议按能力依赖推进，而不是同时铺开全部界面。以下为 **3 名开发等效投入、QA 兼职、10 周**的参考排期；若只有 1 名全栈开发，应只承诺 P0，并将周期调整为 16–20 周。

| 阶段 | 周期 | Android | Windows | 共享与退出条件 |
| --- | --- | --- | --- | --- |
| 基础设计 | 第 1–2 周 | Intent 队列、批注模型设计 | 工作区、文件监听与索引设计 | 固定基准语料；数据迁移、权限与性能方案评审通过 |
| 主路径闭环 | 第 3–5 周 | A-F1、A-F2、A-I1 | W-F1、W-F2、W-I1、W-I2 | 核心流程具备单元测试和端到端测试，无数据丢失 |
| 性能攻坚 | 第 6–7 周 | A-P1、A-P2 | W-P1、W-P2 | 达成首屏、搜索、滚动和内存候选指标 |
| P1 增强 | 第 8–9 周 | A-F3、A-I2、A-I3、A-P3 | W-F3、W-I3、W-P3 | 仅在 P0 无阻断缺陷时合入发布分支 |
| 发布收口 | 第 10 周 | 真机与分享入口矩阵 | Win10/11、安装/卸载与多显示器矩阵 | 无 P0/P1 阻断缺陷；升级、回滚和性能 Gate 全绿 |

## 7. 阶段验收指标

### 7.1 产品指标

- Android 外部文件成功进入正文或明确兜底视图的比例 ≥ 99%。
- Windows 工作区二次访问率、外部修改自动刷新成功率分别纳入本地匿名计数；若不上报遥测，则通过 Beta 测试日志评估。
- 高亮、书签、标签、工作区配置升级后保留率为 100%，迁移失败不得删除旧数据。
- 两端核心任务均可在离线状态完成，远程 HTML 资源除外。

### 7.2 性能与稳定性指标

- Beta 无崩溃会话率 ≥ 99.7%。
- 1 MB 文档文内搜索首个结果 P95 ≤ 100 ms，上一处/下一处切换 P95 ≤ 50 ms。
- 10 MB 文档打开、搜索、连续滚动和恢复位置均不得崩溃；超过设备安全阈值时提供源码模式兜底。
- 自动化 Gate 覆盖 Web build、lint、单元测试、Android lint/构建、Rust 测试及两端核心端到端流程。
- 相同语料相对 v1.1.2 的关键耗时或峰值内存回退超过 10% 时阻断发布。

## 8. 风险与决策点

| 风险/决策 | 影响 | 建议 |
| --- | --- | --- |
| 分块渲染可能破坏搜索、目录和批注锚点 | 两端共同的最高技术风险 | 先建立统一文本偏移和标题锚点协议，再改渲染层 |
| Windows 全文索引体积与隐私 | 大工作区可能占用较多磁盘 | 默认只索引受支持文本；显示索引大小并允许暂停、清理和排除目录 |
| Android 压缩包连续阅读的缓存增长 | 长期使用可能积累大量资源 | 按包设配额，采用最近使用回收；收藏内容清理前二次确认 |
| 文件变化后批注失效 | 影响用户信任 | 使用标题、前后文和内容哈希组合定位，无法可靠恢复时不静默迁移 |
| 多标签与大文档叠加导致内存上涨 | Windows 稳定性下降 | 后台标签冻结重型组件，只保留文档会话和可恢复位置 |
| 发布包仍未签名 | Android 安装升级、Windows SmartScreen 体验不稳定 | 将 Android 正式签名和 Windows 代码签名作为独立发布工程事项，不与功能验收混用 |

## 9. 建议首批进入任务池

1. 先完成跨平台分块渲染与稳定锚点技术验证，决定 A-P2/W-P2 是否可按期进入。
2. Android 并行实现 A-I1，解决所有外部入口的请求可靠性。
3. Windows 并行实现 W-F1 + W-F2 的最小闭环，再扩展 W-P1 全文索引。
4. 批注先交付书签和高亮，再增加备注及导出，避免一次引入过多数据模型。
5. 第 2 周末锁定基线指标；任何新功能不得绕过 HTML 沙盒、缓存配额和数据迁移测试。
