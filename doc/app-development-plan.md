# 《轻页》App 开发任务计划

版本：v1.0  
日期：2026-06-05  
状态：初稿  

## 1. 开发目标

本计划用于指导《轻页》App 的第一阶段开发。

第一阶段不继续停留在原型设计，直接进入 App 工程开发。当前设计决策如下：

1. **正常启动 App**：进入“文件台”首页，对应视觉方向 1。
2. **从微信 / 文件管理器打开文件**：直接进入“阅读幕”文件阅读页，对应视觉方向 2。
3. **第一阶段重点**：先构建基础 App、完成主要页面设计、实现 Markdown 基础浏览，再实现 HTML 浏览，最后逐步优化 Markdown / HTML 的显示细节。

## 4. 版本拆分

## 4.1 M0：工程初始化

目标：创建可运行、可构建 APK 的基础 App 工程。

任务列表：

1. 初始化 `mobile-app` 前端工程。
2. 配置 React + TypeScript + Vite。
3. 安装基础依赖：
   - `@capacitor/core`
   - `@capacitor/cli`
   - `@capacitor/android`
   - `@capacitor/app`
   - `@capacitor/filesystem`
   - `@capacitor/share`
   - `lucide-react`

4. 初始化 Capacitor。
5. 创建 Android 工程。
6. 设置 App 基础信息：
   - App 中文名：轻页
   - 英文名：LightPage
   - Android package name：建议使用 `com.lightpage.reader` 或 `com.fastviewer.app`

7. 参考 `ClassUseCount` 创建 `build-apk.bat`。
8. 完成首次 `npm run build`。
9. 完成首次 `npx cap sync android`。
10. 完成首次 `gradlew assembleDebug`。

验收标准：

1. 本地可以运行 Vite 开发服务器。
2. Android 工程可以成功同步。
3. 可以生成 debug APK。
4. APK 安装后能打开一个基础空白 App。

## 4.4 M3：外部文件打开入口

目标：支持从微信、文件管理器等外部 App 打开文件，并直接进入阅读页。

任务列表：

1. 配置 Android `AndroidManifest.xml` Intent Filter。
2. 支持 MIME 类型：
   - `text/markdown`
   - `text/x-markdown`
   - `text/html`
   - `application/xhtml+xml`
   - `text/plain`
   - `*/*` 兜底，需在 App 内二次判断扩展名

3. 支持扩展名：
   - `.md`
   - `.markdown`
   - `.html`
   - `.htm`

4. 处理 Android 外部传入 URI。
5. 使用 Capacitor 或原生桥接读取文件内容。
6. 建立文件打开状态机：
   - `idle`
   - `loading`
   - `loaded`
   - `unsupported`
   - `error`

7. 外部打开成功后直接进入阅读页。
8. 外部打开失败时进入错误状态。

验收标准：

1. 从 Android 文件管理器选择 `.md` 文件时可以用轻页打开。
2. 从 Android 文件管理器选择 `.html` 文件时可以用轻页打开。
3. 外部打开文件时不进入首页，而是直接进入阅读页。
4. 不支持的文件类型有明确提示。

## 7. 近期技术风险

### 7.1 Android 外部文件 URI

不同 App 传入的文件 URI 可能差异较大，尤其是微信、文件管理器和网盘。需要尽早验证真实 Android 设备上的外部打开流程。

### 7.2 HTML 安全渲染

HTML 文件必须默认禁用危险行为。实现时不能只把 HTML 字符串直接塞进页面，需要明确沙盒策略。

### 7.3 编码识别

GBK / GB2312 文件在 Web 技术栈中需要额外处理。建议在 M10 阶段引入专门编码库。

### 7.4 PDF 导出

移动端 PDF 导出可能涉及 WebView、打印服务、插件能力和样式分页，建议后置到 Markdown / HTML 阅读稳定之后。

### 7.5 微信打开文件

微信对“用其他应用打开”的支持和文件 URI 暴露方式可能随 Android 版本、微信版本和设备厂商变化。需要真机测试。

## 8. 后续执行方式

后续开发建议按任务编号逐步执行。

每完成一个阶段，应至少做一次：

1. `npm run build`
2. `npx cap sync android`
3. Android debug APK 构建
4. 真机或模拟器主流程验证

阶段内如遇到范围膨胀，应优先保证主路径：

**正常启动进入首页 → 点击文件进入阅读页 → Markdown 可读 → 外部打开文件进入阅读页 → HTML 可读。**
