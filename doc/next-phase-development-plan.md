# 《轻页》下一阶段开发计划（功能与性能优化）

版本：v1.1（规划稿）  
规划日期：2026-07-17  
建议周期：6 周  
建议配置：2 名开发（前端/Capacitor、Android/全栈各 1 名）+ 0.5 名 QA，设计按需支持

## 1. 结论与阶段目标

现有 App 已经完成从“打开文件”到“阅读、搜索、目录、编码切换、压缩包导入、导出分享”的主要闭环，工程也能通过 Web 构建、TypeScript/ESLint 检查和 Android Debug 构建。下一阶段不宜继续横向堆功能，而应把产品从“功能可演示”推进到“可稳定发布”。

下一阶段的核心目标有三项：

1. **先消除数据层和 I/O 主路径风险**：正文、原始 Base64、压缩包资源目前集中存放在同步浏览器存储，并会随阅读位置变化反复序列化；这是大文件卡顿、容量溢出和数据丢失的首要风险。
2. **补齐用户承诺与实际行为的差距**：真正实现“粘贴打开”、外部资源询问/单次允许、跟随系统主题、可分享 PDF、目录当前位置高亮等能力。
3. **建立可发布的质量门槛**：补测试、基准、真机矩阵、Android lint 和安全用例，用数据判断是否达到 v1.0 发布标准。

阶段完成的定义：支持的 Markdown/HTML/ZIP/RAR 文件可稳定打开；1 MB 文档首屏 P95 不超过 1 秒；滚动期间不再同步保存全文；Android lint 无错误；核心自动化用例全部通过；发布候选包完成至少 3 类真机验证。

## 4. 关键问题与优先级

### P0：本阶段必须完成

#### 4.1 重构文件存储与阅读进度保存

当前文档数组包含正文、原始 Base64 和压缩包资源，并通过 `localStorage.setItem(JSON.stringify(value))` 同步保存。阅读页又在滚动事件中更新文档记录，文件越多、内容越大，序列化和写入成本越高；压缩包资源允许最多约 40 MB 内联，明显超出这一存储模型的安全范围。

处理方案：

- 浏览器存储只保存设置和轻量索引；正文、原始字节、压缩包资源落到 App 文件目录。
- 文档记录保存 `contentPath`、`originalPath`、资源目录、摘要和状态，不再内联大字段。
- 阅读进度采用 500–1,000 ms 节流，并在退出/切后台时强制落盘一次。
- 阅读位置从单纯像素值升级为“标题锚点 + 段内偏移/进度比例”，降低字号与屏幕变化后的漂移。
- 提供 v1 数据迁移、失败回滚和存储清理策略。

#### 4.2 重构原生 I/O 与压缩包处理

当前文件读取、Base64 编解码、解压、资源内联都在一次调用链内完成，产生多份内存副本；成功解压后的目录也没有随删除记录统一清理。

处理方案：

- 原生读取和解压移到后台执行器，桥接层只返回文件路径和元数据。
- 优先采用流式复制；避免“文件 → Java 字节数组 → Base64 字符串 → JS 字节数组”的全量复制链。
- ZIP/RAR 设置条目数、单条目大小、展开总量、压缩比和目录深度上限；超限中止并清理。
- 文档删除、缓存清理和版本升级时回收解压目录及分享临时文件。
- 大文件默认先进入源码/分段模式，由用户选择是否完整渲染。

建议默认安全阈值（第 1 周用真机数据校准）：最多 1,000 个条目、展开总量 200 MB、单资源 20 MB、压缩比 100:1、目录深度 20 层。

#### 4.3 收紧 HTML 信任边界

默认沙盒策略方向正确，但可信模式同时允许脚本、同源、表单、弹窗和模态能力，且外部链接确认只在脚本禁用时挂载。下一阶段应把“可信”拆成可解释、最小授权的能力集合。

处理方案：

- 保留默认严格沙盒；避免同时授予不必要的 `allow-same-origin` 与脚本权限。
- 将“允许外部资源”“允许脚本”“允许表单/弹窗”拆分，不用一个开关全放行。
- 外部跳转统一经 App 侧确认，不允许可信脚本绕过。
- 外部资源策略提供“默认阻止、每次询问、仅本次允许”，并在页面显示被阻止项数量。
- 增加恶意 HTML、跳转、下载、表单、弹窗和资源加载测试语料。

#### 4.4 建立发布质量门槛

- 修复 Android lint 阻断项，逐条处理或有依据地基线化警告。
- 拆出编码、文件模型、HTML 清理、路径解析、搜索和阅读位置等可测试模块。
- 新增单元测试、组件测试、原生插件测试和关键端到端场景。
- CI 固定执行 Web build、ESLint、单元测试、Android assemble 和 lint。

### P1：本阶段应完成

#### 4.5 补齐功能承诺

- **粘贴打开**：读取剪贴板文本，识别 Markdown/HTML，先展示格式与安全预览，再保存为临时文档；无权限时给出明确引导。
- **外部资源控制**：现有代码已识别外部资源，但缺少“仅本次允许”的实际入口，应补提示条和设置策略。
- **跟随系统主题**：增加 `system/light/dark` 三态，监听系统主题变化。
- **目录增强**：当前标题高亮、层级折叠、返回原阅读位置；长目录增加搜索。
- **文件库语义**：区分“最近访问记录”和“已持久保存文件”，支持排序、筛选、存储占用和批量清理。
- **可靠导出**：Android 生成真实 PDF 文件后调起分享；分享原文件始终保留原始字节，不因大文件退化为 UTF-8 重写。
- **独立 HTML 相对资源**：支持通过系统目录授权解析同目录图片/CSS，而不是仅在压缩包内生效。

### P2：有余量再做

- 首页文件卡片改为单行主操作，收藏/删除收进滑动或更多菜单，提升长列表信息密度。
- 文件名/正文全局搜索、最近/大小/名称排序。
- 导出图片增加“当前可见区域 / 全文 / 分页长图”选择和长度预估。
- 可选的阅读排版设置（行高、内容宽度、代码字号）。

## 5. 性能优化专项

### 5.1 启动与包体

- 动态加载 `html2canvas-pro`，只在导出图片时下载/初始化。
- 阅读器、设置页、HTML 处理和导出模块按路由/能力拆包。
- 代码高亮改为常用语言白名单，其他语言按需加载；普通文档不初始化全部高亮能力。
- Release 开启 R8/资源压缩并清理未使用 Android 资源、重复图标和启动图。

目标：主入口 JS 小于 450 KB（gzip 小于 150 KB）；导出能力独立异步分包；Release APK 小于 8 MB，最终值以功能完整构建为准。

### 5.2 打开与渲染

- 解码、标题提取、搜索索引等纯计算移到 Web Worker 或原生后台线程。
- 以 1 MB、5 MB、10 MB 为分档：小文件完整渲染；中等文件延迟代码高亮和图片；大文件优先源码/分段阅读。
- Markdown 组件映射、HTML 清理结果和标题索引稳定缓存，减少无关状态导致的全文重渲染。
- HTML 高度更新合并到动画帧，限制 `ResizeObserver` 频率。

### 5.3 搜索与滚动

- 搜索输入 120–180 ms 防抖，只在关键词变化时重建匹配；上一处/下一处只移动当前命中，不重新遍历全文。
- 搜索索引保存文本偏移，避免每次增删 `<mark>` 都扫描全部文本节点。
- 滚动事件只更新内存进度，节流持久化；列表超过 100 项后启用窗口化渲染。
- 使用 Performance API 记录打开、首屏、完整渲染、搜索响应和导出耗时。

### 5.4 导出与内存

- 图片导出先测算像素与内存，超过阈值自动降采样或分页，避免超大 Canvas。
- 及时释放 Object URL、临时文件、Canvas 和 iframe；分享结束后延迟清理缓存。
- 对文件读取、解压、HTML 渲染和图片导出记录峰值内存与失败原因。

## 8. 验收指标

### 8.1 主指标

1. **支持文件打开成功率**：成功进入阅读或明确兜底视图的受支持文件数 / 受支持文件尝试数；Beta 阶段目标 ≥ 98%。
2. **1 MB 文档首屏时间**：从收到 URI/选择完成到首屏正文可见；主流测试机 P95 ≤ 1 秒。
3. **无崩溃会话率**：Beta 会话中未发生 Java/JS 崩溃的会话占比；目标 ≥ 99.5%。

### 8.2 驱动指标

- 5 MB Markdown/HTML 首屏 P95 ≤ 2.5 秒；10 MB 文件进入可操作兜底视图 P95 ≤ 1 秒。
- 1 MB 文档搜索首个结果 P95 ≤ 150 ms；上下结果切换 P95 ≤ 50 ms。
- 连续滚动期间不触发正文/资源全量序列化；进度写入频率不超过每秒 1 次。
- 主入口 JS < 450 KB、gzip < 150 KB；导出模块独立分包。
- Android lint 0 错误；P0 场景自动化通过率 100%。

### 8.3 保护指标

- 压缩包超限、损坏、加密或路径异常时不写出越界文件，临时目录可回收。
- 默认 HTML 不执行脚本、不自动跳转、不自动下载；外部资源未经授权不联网。
- 迁移失败不丢失旧数据；删除文件后正文、资源和解压目录无孤儿残留。
- 5 MB 文件打开与滚动期间新增 PSS 峰值先以 < 100 MB 为候选门槛，第 1 周基线后锁定。

## 9. 测试与发布矩阵

### 文件语料

- Markdown：空文件、普通文档、1/5/10 MB、超长单行、超大表格、大量代码块、远程/相对图片、UTF-8/GBK/GB18030。
- HTML：片段/完整文档、内联/外链 CSS、相对资源、脚本、跳转、下载、表单、弹窗、畸形 DOM。
- 压缩包：ZIP、RAR4、RAR5、加密包、中文文件名、深层目录、重复名、路径穿越、压缩炸弹、超限资源。

### 设备与系统

- Android 8/10/12/14 或可获得的相邻覆盖版本。
- 低端 4 GB 内存设备、主流中端设备、高分辨率设备各至少 1 台。
- 文件管理器、微信/类似分享入口、邮件附件、网盘入口各验证一次 URI 行为。

### 发布 Gate

- Web build、ESLint、单元测试、Android assemble、Android lint 全绿。
- P0 端到端用例全绿；安全语料无越权行为；性能指标无回退超过 10%。
- 无 P0/P1 未解决缺陷；已知 P2 问题有用户可理解的兜底。
- Release 包签名、版本号、隐私说明、备份策略、图标和启动图检查完成。

## 10. 前 10 个工作日的具体任务

1. 修复 Manifest Intent Filter 与权限声明顺序，建立 lint 零错误基线。
2. 建立 1/5/10 MB Markdown、HTML、ZIP/RAR 测试语料和计时脚本。
3. 记录首屏、完整渲染、搜索、滚动、导出和峰值内存基线。
4. 定稿 `DocumentMetadata`、正文目录、原始文件目录和资源目录模型。
5. 实现旧 `localStorage` 数据扫描、迁移、校验、回滚和清理。
6. 将阅读进度保存改为节流 + 退出强制保存。
7. 原生插件改为后台执行和路径返回，先覆盖普通文件，再覆盖 ZIP/RAR。
8. 加入解压条目数、展开大小、压缩比、目录深度和单资源限制。
9. 完成 HTML 权限拆分设计与恶意语料单元测试。
10. 在第 10 个工作日做一次 Gate 评审：只有存储迁移、I/O 和安全路径通过，才进入功能扩展。

## 11. 风险、依赖与待确认事项

- **资源约束**：若只有 1 名开发，建议周期调整为 9–10 周，P2 全部顺延。
- **PDF 方案**：需在第 1 周确定使用 Android 打印框架还是引入 PDF 生成库；选择会影响分页质量和工期。
- **同目录资源授权**：依赖 Android SAF 目录授权，需确认是否接受用户多一次授权操作。
- **RAR 兼容性**：当前库对 RAR5/加密包能力有限；本阶段以清晰提示为准，不建议自研解压。
- **指标采集**：当前没有线上遥测。Beta 前可先使用本地性能日志；若要统计真实成功率和崩溃率，需要另行确认隐私友好的诊断方案。
- **性能目标**：1/5/10 MB 阈值和内存目标是基于需求与代码风险给出的候选值，必须在第 1 周用目标设备校准。
